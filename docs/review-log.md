## 01 · 字面量与变量 / 标识符 / 数据类型

| 层 | 题 | 作答 | 判定 |
|---|---|---|---|
| 1 概念 | 字面量 vs 变量 | 说"容器"；方向说反（写成"字面量指向变量"）；漏答"`18` 有没有名字" | ⚠️ 追问后全对 |
| 1 概念 | 标识符规则 / 规范 | 三条硬性规则 + 三条规范，基本完整 | ✅ |
| 1 概念 | 5 种数据类型 + 怎么查 | int / float / bool / str / None，`type()` | ✅ |
| 1 概念 | `type()` vs `isinstance()` | 只答出"用哪个"，没答出"为什么必须" | ❌ 追问三个表达式后打通 |
| 1 概念 | `bool` 与 `int` | `True + True` = 2，知道 bool 当作 1/0 | ✅ |
| 2 预测 | `"3" * 3` | 预测"都报错"，实际 `333`（字符串重复） | ❌ |
| 2 预测 | `"3" + 3` | 预测报错，实际 `TypeError` | ✅ |
| 2 预测 | 列表 `b += [3]` 后 `a` | 预测 `[1,2,3]`，正确 | ✅**但理由错** |
| 2 预测 | `1 + 1.0` / `type()` / `True + 1` | 全对（`type()` 那题写成 `float`，实际 `<class 'float'>`） | ✅ |
| 2 预测 | `1 == 1.0` | 预测报错，实际 `True` | ❌ |
| 3 产出 | `isinstance` 判断数字 | 写成逐个单类型判断，漏了元组写法；`v = True` 时打印 `True` | ⚠️ |
| 3 产出 | 3 个非法标识符 | 结论对；`True` 的理由写成"特殊字符"，应为**关键字** | ⚠️ |
| 追问 | `"1" == 1` | 答 `False` —— 模型已修正 | ✅ |
| 追问 | `b = b + [3]` 后 `a` | 答 `[1,2,3]`，实际 `[1, 2]` | ❌（推翻上面对 `+=` 的判断） |

**诊断**

- 主缺口是**「说得出、推不动」**：概念题 5 题里 3 题直接答对，但预测题错 2 个、追问错 1 个。
- 有一条**贯穿性误解**：默认"类型不同 → 报错"。它同时造成 `"3" * 3` 和 `1 == 1.0` 两处误判。
- `+=` 与 `+` 的区别没建立 —— 题 B 是路径侥幸，靠判别性追问才暴露。
- 元组写法 `isinstance(v, (int, float))` 是全新知识，第一次见。
